### 2. 黄仁勋被美国国会要求闭门简报
- 来源：wccftech  
  https://wccftech.com/nvidia-ceo-jensen-huang-congress-closed-door-briefing-china-spying-national-security
- **材料说了什么**：标题称其因与一名“处于联邦间谍调查焦点”的高管互动，被国会要求闭门简报。
- **为什么重要**：说明 AI 芯片公司已处于美国国家安全审查的中心。科技公司高管的对外接触、供应链合作可能被政治化。
- **对你有什么用**：这类新闻会影响市场情绪和出口管制预期，但**材料没有提供调查结论**，不要把标题当成“已定罪”。对个人而言，关注官方和路透等一手报道，少看二手标题。

### 3. OpenAI 发布 GPT‑6 Cyber：面向网络安全的对齐 Agent
- 来源：OpenAI  
  https://openai.com/index/introducing-gpt-6-cyber
- **是什么**：一个网络安全模型，用于发现可利用漏洞并开发修复，训练目标是“保持在授权范围内”。
- **趋势影响**：AI Agent 正在从“通用聊天”走向“垂直高风险场景”。安全领域的关键不只是能力，而是**授权边界、审计和可控性**。
- **对你有什么用**：如果你做 Agent 项目，应该从第一天就设计“工具权限”和“操作日志”，而不是只追求自动化。这是后端工程经验能直接迁移到 AI 的地方。

### 4. OpenAI 推出 BioBasicsBench：评估 AI Agent 做湿实验室科学
- 来源：OpenAI  
  https://openai.com/index/measuring-how-ai-agents-handle-wet-lab-science
- **是什么**：100 个任务的基准，衡量 Agent 解读原始实验数据、处理日常湿实验室工作的能力。
- **趋势影响**：Agent 评估正在从“考试题”转向“真实工作流”。这对 RAG 和 Agent 开发者是个信号：**能演示不等于能评估**，以后更看重可重复的任务基准。
- **对你有什么用**：你做 RAG 项目时，应该自己建一个小型测试集（比如 20 个问题和标准答案），记录准确率、失败类型。这比堆功能更能体现工程能力。

### 5. GitHub 项目 ryugi：给 coding agent 用的 skills 集合
- 来源：GitHub  
  https://github.com/Innei/ryugi
- **是什么**：一个面向 coding agents 的 skills 集合，附带 artifacts 工作台：实时画板、可评论文档、HTML 测试台、TDD 构建。JavaScript，约 365 stars。
- **为什么值得看**：它代表一种趋势——把 Agent 的能力拆成可复用的“技能”，并配上可检查的产物（文档、测试台）。
- **对你有什么用**：**适合参考思路，不适合初学者直接通读源码**。项目较新、star 不算多，文档和稳定性未必适合当教程。你可以只看它的 skills 目录如何组织、每个 skill 的输入输出怎么定义。

## 二、GitHub 热门项目

### 1. Innei/ryugi
- 链接：https://github.com/Innei/ryugi
- 语言：JavaScript｜约 365 stars
- **适合你吗**：**部分适合**。你关注 AI Agent 和自动化工具，这个项目的“skills 集合 + 可检查产物”思路值得学。但它是新项目，不是系统教程；如果你是编程初学者，建议只读结构，不逐行啃。
- **怎么用**：花 30–60 分钟看 README 和目录，回答三个问题：一个 skill 由哪些文件组成？输入输出是什么？如何测试？然后模仿写一个最小 skill。

### 2. jaisurya-dev-art/rigby2d
- 链接：https://github.com/jaisurya-dev-art/rigby2d
- 语言：JavaScript、Rust，含 Godot/Unity runtime｜约 161 stars
- **是什么**：开源 2D 骨骼动画编辑器，支持 PSD 自动绑定、网格/IK/物理、音频口型同步、导出 JSON/.skel，内置面向 AI 助手的 MCP server。
- **适合你吗**：**不适合作为主学习项目**。功能面很宽，涉及图形、动画、Rust、游戏引擎，初学者容易被复杂度淹没。
- **可借鉴点**：它内置 MCP server，说明“桌面工具 + AI 助手接口”正在成为常见设计。你可以只看 MCP 接口部分，理解 AI 助手如何调用外部工具。

### 3. do-whilefor/zcode2api
- 链接：https://github.com/do-whilefor/zcode2api
- 语言：Go｜约 120 stars
- **是什么**：材料称其为 ZCode（智谱、Zai）的“反代”，优化免费账号并发重试，支持免费额度。
- **适合你吗**：**不建议作为学习项目，更不建议用于生产**。这类“反代/薅免费额度”项目通常涉及服务条款和账号安全风险。材料没有说明合规性，不能假设它被官方允许。
- **可借鉴点**：如果你学 Go，可以看它如何处理并发重试和限流，但不要照搬其用途。

## 三、AI 发展动态

1. **Agent 评估走向垂直化**  
   BioBasicsBench 说明：以后评价 Agent，不是看它“会不会聊天”，而是看它能否在具体工作流中处理原始数据。  
   对你的影响：做 RAG/Agent 项目时，**测试集和失败分析比功能列表更重要**。

2. **安全 Agent 成为独立方向**  
   GPT‑6 Cyber 和 OpenAI 与 Hacktron 的合作都指向：AI 被用于找漏洞、修漏洞、测试第三方连接。  
   对你的影响：后端转 AI 时，“安全 + Agent”是一个有工程门槛的方向，比纯 prompt 调优更稳。你可以先学基础的 Web 安全、权限控制、日志审计。

3. **Agent 的“授权边界”被明确强调**  
   GPT‑6 Cyber 的材料明确提到“训练保持在授权范围内”。这说明高风险 Agent 的核心问题是可控性。  
   对你的影响：你写自动化工具时，应默认加“人工确认”和“操作范围限制”，这会成为面试和项目展示的加分项。

## 六、对我的个人建议

### 本周优先做（按顺序）

1. **给现有 RAG/Agent 项目补一个 20 题测试集**  
   学 BioBasicsBench 的思路：记录问题、标准答案、模型输出、失败原因。  
   产出：一个 `eval.md` 或简单脚本。这比再加一个功能更能证明你会做 AI 工程。

2. **只读 ryugi 的结构，不啃源码**  
   目标：搞清一个 “skill” 的文件组成和输入输出。然后自己写一个最小 skill，比如“读取指定网页并生成摘要”。  
   时间盒：2 小时。看不懂就停，不要陷进去。

3. **给自动化工具加权限边界**  
   参考 GPT‑6 Cyber 的“授权范围”思路：你的 Agent 调用外部工具前，是否有白名单？是否有日志？是否需要人工确认？  
   这是后端经验能直接迁移的地方。

4. **不要碰 zcode2api 这类反代项目**  
   可以看并发重试的写法，但不要用于实际账号或生产。服务条款和账号风险材料没有说明，不能假设安全。

5. **政策信息单独建源**  
   本期政策材料无效。建议收藏中国政府网、国务院部门页面，每周固定看一次原文；公考备考不要依赖二手简报。国际新闻优先看路透、官方声明，少看只有标题的聚合新闻。

### 中期方向

- **后端转 AI 的切入点**：不要只学 prompt。优先补“评估、权限、日志、部署”这些工程能力，再结合 RAG 做一个小型可演示项目。
- **RAG 学习路径**：先做一个可用的文档问答，再加测试集，再加权限和引用来源。不要一上来做多 Agent。
- **公考/政策**：把“科技政策、出口管制、算力政策”作为常识积累，但每次以政策原文为准。
